# dst v2: a short guide

This guide shows the parts of dst v2 with one small example each. The full
design is in [v2-design.md](v2-design.md). The real code is in
`examples/kv` and `examples/kvchaos`. Read those when you want the whole picture.
The examples here are cut down, so they do not compile as they are. The names
and signatures are real.

## The idea

dst runs a test as a simulation. Nothing real runs. There is one random
number stream, one fake clock, and one queue of events. Each run uses one
seed number. The same seed always gives the same run, so a bug that a seed
finds can be run again and again.

Your code has two kinds of parts:

- **machines**: they hold state. They take one input and give back outputs.
  They never do IO, never read the real clock, and never start goroutines.
- **the world**: the kernel. It runs the machines, sends messages between
  them, fires timers, and makes faults.

The same machine can also run in production with the `live` package.

## 1. A machine

A machine implements `machine.Machine[In, Out]`:

```go
type Machine[In, Out Message] interface {
	Step(now Now, in In) []Out
	StateHash() uint64
}
```

`Step` takes one input and returns a list of outputs. It is the only place
where the state changes. `StateHash` is a hash of the whole state. The kernel
adds it to the trace hash after each step.

Inputs and outputs are sum types. A sum type is an interface with a marker
method. Each case has a fixed tag number and a `Fold` method, so the trace hash
does not depend on Go type names:

```go
// clientIn is every input of the client.
//
//sumtype:decl
type clientIn interface {
	machine.Message
	Tag() uint64
	isClientIn()
}

type getResponse struct{ Key, Value, Want string }

func (getResponse) isClientIn()      {}
func (getResponse) Tag() uint64      { return 3 }
func (m getResponse) Fold(h *trace.Hash) { fold3(h, m.Tag(), m.Key, m.Value, m.Want) }
```

The `//sumtype:decl` comment lets the `gochecksumtype` linter check every
type switch over the interface.

## 2. Typed routing

A machine gives back plain values. A **route function** turns each output into
a kernel call. It is one type switch over every output case:

```go
Route: func(r *kernel.Router[serverIn], out serverOut) {
	switch x := out.(type) {
	case storePut:
		kernel.Call(r, store, storeReq(x))
	case reply:
		kernel.Send(r, client, clientIn(getResponse(x)))
	case waitNext:
		r.SetTimer(x.ID, x.After, nextOp{})
	}
}
```

Each node has its own input type. `kernel.Addr[In]` is made only by
`kernel.Spawn`. So sending a message of the wrong type does not compile.
When a message is a case of a bigger sum type, convert it first:
`kernel.Send(r, server, serverIn(putRequest(x)))`.

## 3. A node

A node is spawned with a `kernel.NodeSpec`. It says how to build the
machine, how to route its outputs, and what the first input is:

```go
client = kernel.Spawn(w, kernel.NodeSpec[clientIn, clientOut]{
	Name: "c1",
	New: func(env machine.Env, _ machine.NodeInstance) machine.Machine[clientIn, clientOut] {
		return &clientMachine{env: env, script: script}
	},
	Route: routeClient,
	Boot:  func(machine.NodeInstance) clientIn { return begin{} },
})
```

`New` runs on every boot. `Boot` makes the first input of every boot. A
crash ends one boot, and nothing in memory survives it.

## 4. A service

A service is an outside system: an object store, a network, a shared log. It
has a `Handle` method. `Handle` must draw all its random numbers at once, when
the request is made. Every answer is a later `Deliver`, never an answer given
at once:

```go
type store struct{ data map[string]string }

func (s *store) Name() string                          { return "store" }
func (s *store) StateHash() uint64                     { return 0 }
func (s *store) EnterRecovery()                        {}
func (s *store) OnCrash(*kernel.ServiceContext[serverIn], machine.NodeInstance) {}
func (s *store) Handle(cx *kernel.ServiceContext[serverIn], from kernel.Ref[serverIn], req storeReq) {
	// draw the delay here, then answer later with cx.Deliver
}

st := kernel.AddService[storeReq, serverIn](w, &store{data: map[string]string{}})
```

## 5. A lane

Messages on one lane arrive first in, first out. A lane is a number. You make
lanes with a key of any comparable type:

```go
lanes := kernel.NewLanes[string](w)
lane := lanes.Get("client-1") // the same key gives the same lane for the whole run
kernel.SendOn(r, lane, server, serverIn(putRequest(x)))
```

## 6. A phase

A run has three phases: faults on (`PhaseFaults`), faults off with the nodes
still up (`PhaseRecovering`), and the drain (`PhaseRecover`). The kernel
sets the phases from a schedule:

```go
kernel.SchedulePhases(w, kernel.Phases{
	Chaos:    20 * machine.Second, // faults on
	Settling: 5 * machine.Second,  // faults off
	Settle:   5 * machine.Second,  // drain
})
w.RunUntil(nil)
res := w.Finish()
```

Fault never fires outside the fault phase. A driver node can hear the phase
change through its `OnPhase` function.

## 7. A spec with Lockstep

A **spec** is a short program with no faults. It gives the right answer. A
**subject** is the real code. `spectest.Lockstep` makes random lists of
operations, runs each list on the spec and on the subject, and compares the
answers. When the answers differ, it shrinks the list to a short one and
prints the Go code and the command that runs the seed again.

```go
type Spec[Op, Res any] interface {
	Apply(op Op) Res
	StateHash() uint64
}

lock := spectest.Lockstep[Op, Res, *subject]{
	Name:       "kv.Op",
	NewSpec:    func() spectest.Spec[Op, Res] { return &kvSpec{} },
	NewSubject: func(t *rapid.T) *subject { return newSubject() },
	Ops:        spectest.SimplestFirst(opGen),
	Equal:      equalRes,
	Rerun:      spectest.Rerun{EnvPrefix: "P"},
}
lock.Check(t) // reads P_SEED, P_CAMPAIGN and P_SEEDS
```

`faulty.New` (package `check/faulty`) can put slow replies, errors, timeouts and
lost answers around a spec. The spec does not change. The faults are only in
the wrapper.

## 8. A planted bug

A planted bug is a mistake that a test puts into the code on purpose. It
proves that the checks catch real mistakes. A test has two rules:

- every bug must be caught by some seed from 1 to the budget
  (`spectest.RequireCaught`);
- with no bug on, no seed may fail (`spectest.RequireClean`).

```go
const bugRemoveLast spectest.Bug = "remove does nothing when the set has one number"

spectest.RequireCaught(t, []spectest.Bug{bugRemoveLast}, 300,
	func(bug spectest.Bug, seed uint64) bool {
		return runOneSeed(bug, seed) // true when the check failed
	})
spectest.RequireClean(t, 60, func(seed uint64) bool {
	return runOneSeed("", seed)
})
```

## 9. A campaign scenario

A campaign runs many seeds of one or more scenarios. It prints a report: the
counts, the failed seeds with the command that runs each one again, the
assertions that were never reached, and the faults that never fired. Each
scenario is one function from a seed to a result:

```go
reg := &campaign.Registry{}
reg.Add(campaign.Scenario{
	Name:   "kv",
	Detail: "a store with no faults",
	Run: func(seed uint64, o campaign.RunOptions) campaign.Result {
		r := kv.RunWith(kernel.Config{Seed: seed, Log: o.Log, HaltOnFirst: o.HaltOnFirst})
		return campaign.FromKernel(r, "")
	},
})
cfg := campaign.Config{Tool: "kvsim", EnvPrefix: "MDS"}
os.Exit(campaign.Main(cfg, reg, os.Args[1:], os.Stdout, os.Stderr))
```

Run it with the commands from `examples/kvsim`:

```bash
go run ./examples/kvsim -seeds 200 -report         # 200 seeds, with the report
go run ./examples/kvsim -scenario kvchaos -seed 7  # one seed, with its step log
MDS_CAMPAIGN=30s go run ./examples/kvsim           # seeds until 30 seconds have passed
```

## Names of the parts

| Part | Package | Main names |
|---|---|---|
| machine | `machine` | `Machine`, `Env`, `Now`, `Duration` |
| world and routing | `kernel` | `New`, `Spawn`, `AddService`, `Send`, `Call`, `Router` |
| lanes and phases | `kernel` | `NewLanes`, `SendOn`, `SchedulePhases` |
| production loop | `live` | `Run` (not in the determinism gate) |
| spec checks | `check/spectest` | `Spec`, `Lockstep`, `Bug`, `RequireCaught`, `RequireClean` |
| faulty service | `check/faulty` | `New`, `Faults`, `Shape` |
| campaign | `campaign` | `Registry`, `Scenario`, `Config`, `Main` |
| assertions and faults | `assert`, `fault` | `NewAlways`, `NewSometimes`, `NewReachable`, `NewSite` |
